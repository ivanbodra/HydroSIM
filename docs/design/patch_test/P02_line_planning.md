# P2 — Patch-Test Planning — Visual Treatment

Pedagogy: `docs/pedagogy/patch_test/P02_line_planning.md`  
Science: `docs/science/patch_test_module_scientific_contract.md` §4

## Visual purpose

Teach whether a proposed survey geometry can identify the chosen classic residual before acquisition begins.

Learner question: **Will this plan observe enough of the same physical seabed, with the correct geometric contrast, to support the intended Patch Test?**

## Dominant composition

The main instrument is a **top-down survey-planning map** with a linked profile/terrain inset when needed.

The common-support region must be explicit. Adequacy cannot be represented only by a badge or score.

## Primary interaction

- target residual family;
- line relation/direction;
- offset/separation where relevant;
- speed pair for latency;
- terrain/feature preset;
- canonical swath/support visualization.

Keep depth/slope/separation/speed controls limited to scenario-supported pedagogical ranges. Do not imply universal thresholds.

## Parameter-specific planning grammar

### Roll

Show reciprocal passes on the same nominal line and common across-track swath support. Flat/uniform comparison terrain is visually preferred for the isolation exercise.

### Pitch

Show reciprocal passes with the same nominal speed over a distinct along-track slope/feature. Highlight the common profile/surface actually used for comparison.

### Yaw / Heading

Show two laterally offset, parallel, same-direction lines. The common **outer-swath** region and the identifiable feature/slope inside it must dominate the scene.

### Latency

Show the same line/direction at two materially different speeds over the same distinct feature/profile. Equal-speed plans should visibly lose the differential timing cue.

## Adequacy display

Use `Adequate`, `Suboptimal`, or `Inadequate` only together with spatial evidence and a concise reason such as:

- no common seabed;
- wrong line-direction relationship;
- no speed contrast;
- feature/slope absent;
- common support too weak.

## Interaction affordance

Allow direct manipulation where practical: drag line separation/offset or choose canonical presets, with immediate geometry response. Avoid freeform mapping controls that add complexity without supporting the Patch Test concept.

## Visual hierarchy

1. line geometry and headings;
2. swath/common-support region;
3. terrain feature needed for observability;
4. adequacy state/reason;
5. supporting metrics.

## Acceptance

P2 passes when the learner can explain visually why a plan is Adequate/Suboptimal/Inadequate and can distinguish the required planning geometry for Roll, Pitch, Yaw/Heading and Latency.
