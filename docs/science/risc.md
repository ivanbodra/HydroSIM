# Rigorous Inter-Sensor Calibrator (RISC)

Version: 0.1.1

## 1. Purpose

This document records the scientific basis and HydroSIM implementation semantics of the Rigorous Inter-Sensor Calibrator (RISC) described by Brandon A. Maingot (2019).

RISC belongs inside HydroSIM because it diagnoses and estimates parameters of the acquisition/integration system itself. It is not a seafloor-surface estimator such as CUBE and is not treated as downstream bathymetric product generation.

RISC is a research calibration method, not an established hydrographic calibration standard. HydroSIM reproduces and investigates the published method; this does not constitute independent validation of field performance.

HydroSIM has two distinct reasons to retain RISC capability:

1. didactic demonstration of dynamic integration errors and their bathymetric signatures; and
2. controlled scientific evaluation of the capability, observability, sensitivity, and limitations of the RISC method itself.

The second role is particularly important because a simulator has access to known Truth. It can therefore compare injected integration errors directly with parameters recovered by a future RISC estimator, which is generally impossible with equivalent certainty in field data.

## 2. Scientific lineage

The HydroSIM RISC model is grounded primarily in:

1. Hughes Clarke (2003), which formalized characteristic dynamic motion residuals and their bathymetric signatures;
2. Maingot, Hughes Clarke, and Calder (2019), which advanced simultaneous identification and estimation of integration errors;
3. Maingot's 2019 M.S. thesis, which provides the six-parameter RISC formulation and the analytical georeferencing-error equations used here.

Conceptually:

```text
Dynamic motion residual diagnosis
        ↓
Parameterised integration-error model
        ↓
Georeferencing with candidate errors
        ↓
Sounding residuals relative to a local reference surface
        ↓
Parameter estimation
```

HydroSIM currently implements the parameterization and physical forward-model validation. The estimator/optimizer itself is not yet implemented.

## 3. Published six-parameter vector

Maingot Section 2.2 identifies six integration errors:

1. GNSS-MBES X-lever error, `ΔLx`;
2. GNSS-MBES Y-lever error, `ΔLy`;
3. INS-MBES latency, `Δt`;
4. INS scaling, `Δρ`;
5. INS-MB Z-axis misalignment, `Δκ`;
6. SSS Error (latency and/or bias), `ΔSSS`.

The published vector is therefore represented in HydroSIM documentation as:

\[
\boldsymbol{\beta}_M =
[\Delta L_x,\Delta L_y,\Delta t,\Delta\rho,\Delta\kappa,\Delta SSS].
\]

The subscript `M` is used here when a distinction from HydroSIM-native parameter semantics is useful.

## 4. Truth, observation, and configured reconstruction

The most important implementation rule is that an integration error changes the reconstruction of an observation; it does not create a new physical echo.

HydroSIM therefore uses the conceptual chain:

```text
Truth state
    ↓
True beam / propagation
    ↓
True terrain interaction
    ↓
Measured TWTT or range
    ↓
Configured integration state
    ↓
Calculated sounding
```

The Configured branch reuses the same measured observation generated by the Truth branch.

An erroneous configured ray must not be re-intersected with the true terrain to obtain a new range. Doing that would use unavailable truth information and would suppress or distort the physical manifestation of integration errors.

## 5. Latency — Δt

Maingot uses the first-order local expression:

\[
x^* = x - \dot{x}\,\Delta t.
\]

HydroSIM interprets positive latency as an older state:

\[
state_{used}(t)=state(t-\Delta t),\qquad \Delta t>0.
\]

Thus the sign is preserved directly between Maingot and HydroSIM.

The published equation is the first-order Taylor approximation of the exact time-shift semantic. The reference implementation preserves the published equation, while a future higher-fidelity time-series backend may sample or interpolate the actual state at `t - Δt`.

## 6. Motion scale — Δρ

In Maingot's equations, `Δρ` is the total multiplicative scale factor, not an additive scale error:

\[
x_{scaled}=\Delta\rho\,x.
\]

No scale error therefore corresponds to:

\[
\Delta\rho=1.
\]

If HydroSIM later exposes a deviation-from-unity parameter, it must be explicitly related by:

\[
\delta\rho_H=\Delta\rho_M-1.
\]

The reference implementation uses the published total-factor form.

## 7. Z-axis motion-axis misalignment — Δκ

Maingot's coupled roll/pitch equations are represented as:

\[
\omega^* =
\sin^{-1}
\left[
\cos\Delta\kappa\,\sin\left(\Delta\rho(\omega-\dot\omega\Delta t)\right)
+
\sin\Delta\kappa\,\sin\left(\Delta\rho(\psi-\dot\psi\Delta t)\right)
\right],
\]

\[
\psi^* =
\sin^{-1}
\left[
\cos\Delta\kappa\,\sin\left(\Delta\rho(\psi-\dot\psi\Delta t)\right)
-
\sin\Delta\kappa\,\sin\left(\Delta\rho(\omega-\dot\omega\Delta t)\right)
\right].
\]

In Maingot's notation, `ω` is roll and `ψ` is pitch. This differs from HydroSIM's conventional use of `ψ` for yaw/heading and must not be silently mixed.

For small angles:

\[
roll^* \approx scaled\ roll + \Delta\kappa\,scaled\ pitch,
\]

\[
pitch^* \approx scaled\ pitch - \Delta\kappa\,scaled\ roll.
\]

This is a roll/pitch cross-talk mechanism caused by Z-axis misalignment of the motion axes relative to the multibeam reference. It is not a generic vessel-heading error and is not equivalent to a conventional sonar yaw patch-test offset.

The current physical cross-validation fixes an observable sign consequence: for pure positive pitch, positive Maingot `Δκ` produces positive roll cross-talk under the published equation. In HydroSIM's Forward-Starboard-Down convention, that induced positive roll steers a nadir sensor-frame ray toward Port (`-Y`).

## 8. Lever-arm errors — ΔLx and ΔLy

Maingot's erroneous integration uses:

\[
L_{configured}=L_{true}-\Delta L_M.
\]

HydroSIM defines a configuration error as:

\[
\delta L_H=L_{configured}-L_{true}.
\]

Therefore:

\[
\boxed{\delta L_H=-\Delta L_M}.
\]

The relation applies componentwise to `X` and `Y`.

The current second-tier validation does not merely test this algebraic sign conversion. The configured lever arm is passed through the HydroSIM transform chain so the sensor origin and calculated sounding move accordingly while preserving the Truth-derived measured range.

## 9. Surface sound-speed error — ΔSSS

Maingot Section 2.2 describes one effective parameter:

`SSS Error (latency and/or bias)`.

HydroSIM therefore does not split the six-parameter RISC vector into separate SSS-bias and SSS-latency estimated parameters. Those may be physical causes of the instantaneous effective `ΔSSS`, but they are not separate members of the published RISC vector.

The configured SSS relation is:

\[
SSS_{configured}=SSS_{true}-\Delta SSS_M.
\]

If HydroSIM uses configured-minus-truth semantics:

\[
\delta c_s=c_{configured}-c_{true},
\]

then:

\[
\boxed{\delta c_s=-\Delta SSS_M}.
\]

The simple steering relation implemented in the reference module is:

\[
\theta^*=
\sin^{-1}
\left[
\frac{SSS-\Delta SSS}{SSS}
\sin\theta
\right].
\]

This error belongs in beam steering and then propagation. It must not be represented as a generic angular perturbation of vessel or sensor pose.

The current physical cross-validation uses the published simple steering relation followed by homogeneous straight-ray propagation. The more complete Tx/Rx motion-coupled steering expressions and water-column ray tracing remain future work.

## 10. Heave convention note

Maingot's Section 3.1 includes:

\[
Hv^*=\Delta\rho(Hv-\dot Hv\Delta t).
\]

The thesis text used for the current implementation does not directly establish the sign convention of `Hv` strongly enough to declare an internal HydroSIM sign identity.

HydroSIM uses positive heave upward. External multibeam/navigation conventions often use Down-positive vertical axes and may therefore imply:

\[
Hv_M=-heave_H.
\]

This crosswalk remains explicitly marked as pending direct or equivalent-source confirmation and must not be silently embedded in the reference function.

## 11. Reference implementation

The analytical reference implementation is:

```text
src/hydrosim/integration/risc_maingot.py
```

It currently contains:

- Maingot's first-order latency expression;
- motion scale factor;
- coupled roll/pitch Z-axis misalignment equations;
- lever-arm sign crosswalk;
- effective SSS sign crosswalk;
- simple SSS steering relation.

It intentionally does not contain the RISC optimizer.

Reference code is intended to be transparent and scientifically auditable. Future vectorized, C++, or GPU implementations may optimize numerical execution but must reproduce the reference behavior within declared tolerances and must not silently alter the scientific model.

## 12. Validation layers

HydroSIM separates several different claims of correctness.

### Tier 1 — published equation reproduction

Files:

```text
scientific_registry/validation/golden_values/risc_maingot_2019_v0_1.yaml
tests/regression/test_risc_maingot_2019_golden_values.py
```

These tests reproduce the published analytical parameterization and convention crosswalks.

### Tier 2 — physical HydroSIM cross-validation

File:

```text
tests/regression/test_risc_hydrosim_physical_crosswalk.py
```

The current test set covers all six parameters through controlled physical cases:

- `ΔLx`: configured sensor-origin displacement;
- `ΔLy`: configured sensor-origin displacement;
- `Δt`: older motion state with preserved measured range;
- `Δρ`: scaled motion state with preserved measured range;
- `Δκ`: roll/pitch cross-talk with an observable geometric sign consequence;
- `ΔSSS`: SSS-dependent steering followed by homogeneous straight propagation.

Repository CI has executed the complete HydroSIM test suite successfully after these Tier-2 tests were added.

### Tier 3 — reproduction of selected Maingot simulation cases

Deferred until the general HydroSIM survey/acquisition infrastructure naturally provides the required multi-ping time-series, motion, Tx/Rx timing, trajectory, sector, and propagation capabilities. Tier 3 should reuse that infrastructure rather than introduce RISC-specific duplicates.

### Tier 4 — RISC estimator and optimization

Deferred. The estimator is not required for the initial didactic simulator because the student is not expected to iteratively solve the RISC optimization. When implemented, the first estimator should be an offline/batch scientific capability rather than a mandatory real-time component.

### Tier 5 — controlled scientific evaluation of RISC

Planned research capability. Once an estimator exists, HydroSIM can exploit known simulation Truth to evaluate the method itself:

```text
Known Truth
    ↓
Inject known integration errors
    ↓
Simulate acquisition
    ↓
Generate dynamic residual field
    ↓
Run RISC estimator
    ↓
Compare estimated parameters with injected parameters
```

For each parameter, a direct recovery error can be defined as:

\[
e_{\beta_i}=\hat{\beta}_i-\beta_i^{truth}.
\]

Bathymetric performance may also be compared before and after correction, for example with `RMSE_before` and `RMSE_after` against known terrain Truth.

This layer should investigate not only successful recovery but also observability, parameter confounding, sensitivity, and failure cases. Candidate controlled variables include motion amplitude and period, water depth, swath width, terrain roughness, noise, sound-speed conditions, and combinations of simultaneous integration errors.

A scientifically useful negative result is explicitly in scope: HydroSIM should be able to demonstrate conditions under which RISC cannot uniquely or reliably recover the injected parameters.

This scientific evaluation is distinct from reproducing Maingot. Reproduction validates the HydroSIM implementation against the published method; controlled Truth-based experiments evaluate the capability and limitations of the method under synthetic conditions.

### Tier 6 — independent field validation

Separate from implementation correctness and synthetic scientific evaluation. Reproducing the published method or demonstrating parameter recovery against simulation Truth does not establish real-world field performance.

## 13. Execution and didactic role

RISC shall not be a mandatory computational dependency of ordinary HydroSIM experiments. Simple geometry, acoustics, patch-test, or survey demonstrations must not instantiate the RISC estimator.

A future capability model may distinguish:

```text
risc.mode:
    disabled
    visualize_only
    offline_estimation
    research_validation
```

`visualize_only` may use known injected errors to demonstrate characteristic dynamic residuals without running an optimizer. `offline_estimation` may estimate parameters after acquisition. `research_validation` may execute repeated controlled scenarios or parameter sweeps.

Continuous on-the-go RISC correction is not an initial HydroSIM requirement. It may be investigated later if it provides scientific or didactic value, but it must not dictate the architecture or computational requirements of the core simulator.

## 14. Scope boundary

RISC is inside HydroSIM because it estimates properties of the measurement/integration system.

The following conceptual distinction is maintained:

```text
Measurement formation / integration / calibration / diagnosis
    → HydroSIM scope

Observation cleaning / surface estimation / gridding / hydrographic product generation
    → downstream processing scope
```

This is a functional distinction, not a real-time versus post-processing distinction. Modern hydrographic software may execute downstream processing during acquisition, but that does not change the scientific role of the algorithm.
